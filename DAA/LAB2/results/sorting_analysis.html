Experimental and Theoretical Analysis of Bubble Sort, Selection Sort, and Insertion Sort (SVNIT M.Tech CSDS103)

Execution Time vs Input Size Plot

Theoretical vs Experimental Complexity Breakdown

Bubble Sort (Early Exit)

  • Best Case (O(n)): When array is already sorted, terminates after pass 1 ($n-1$ comparisons, 0 swaps) in ~2 µs.
  • Worst Case (O(n²)): On reverse sorted array, requires maximum comparisons $\frac{n(n-1)}{2}$ and $O(n^2)$ swaps (~10–12 ms for $N=500$).
  • Average Case (O(n²)): Randomly permuted elements require quadratic passes.

Selection Sort

  • Invariable Complexity (Θ(n²)): Performs exactly $\frac{n(n-1)}{2}$ comparisons across ALL input types (Random, Sorted, Reverse).
  • Comparisons: $N=50 \to 1,225$, $N=100 \to 4,950$, $N=200 \to 19,900$, $N=500 \to 124,750$.
  • Swap Efficiency: Performs at most $n-1$ swaps, minimizing memory writes despite quadratic comparisons.

Insertion Sort

  • Best Case (O(n)): On already sorted arrays, each item is checked once and requires 0 shifts ($n-1$ comparisons, < 1 µs).
  • Worst Case (O(n²)): On reverse sorted array, requires $\frac{n(n-1)}{2}$ comparisons and maximum element shifts.
  • Empirical Efficiency: Typically 2–3x faster than Bubble Sort on random inputs due to low constant factors ($n^2/4$ avg comps).
