Experimental and Theoretical Analysis of Linear Search and Binary Search (SVNIT M.Tech CSDS103)

Execution Time vs Input Size Plot

Theoretical vs Experimental Complexity Comparison

Linear Search Analysis

  • Best Case ($O(1)$): Target at index 0 requires exactly 1 comparison and consistently executes in ~200–300 ns regardless of array size $N$.
  • Worst / Absent Case ($O(n)$): Target at end or absent requires $N$ comparisons. Execution time scales linearly as $N$ increases from 10 to 200 (0.77 µs → 11.5 µs).
  • Average Case ($O(n)$): Target at middle requires $N/2$ comparisons, scaling linearly.

Binary Search Analysis

  • Best Case ($O(1)$): Target located at middle element on first iteration requires 1-3 comparisons and executes in ~400–600 ns.
  • Worst / Absent Case ($O(\log n)$): Search space halves at every step, requiring at most $pprox \lceil\log_2 N ceil + 1$ comparisons (max 8 comparisons for $N=200$).
  • Scalability: While Linear Search latency increases $15 imes$ from $N=10$ to $N=200$, Binary Search remains nearly constant at ~0.8–1.0 µs.
